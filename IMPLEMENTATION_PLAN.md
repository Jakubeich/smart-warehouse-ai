# Smart Warehouse AI — implementation ledger

Official title: Návrh a experimentální vyhodnocení inteligentního systému pro koordinaci autonomních robotů ve skladovém prostředí.

## Architecture decided before implementation

Python domain models → pure path planners / scheduler → deterministic tick engine → locked orchestration service → FastAPI REST and versioned WebSocket snapshots → React stores → renderer. PostgreSQL stores versioned warehouse/scenario documents and experimental records through SQLAlchemy; Alembic owns schema creation. Active simulations are memory-only and disappear on restart. Planning runs outside the event loop. One backend worker owns active state.

Coordinates are integer (x,y), origin top-left, +x right, +y down. Each cell has a physical metre size. 3D maps cell centres to ((x+.5)*size, 0, (y+.5)*size). Presentation assets never enter planning logic.

Models: Warehouse (sparse typed cells, dimensions, schema version), Robot (configuration + runtime state), TransportTask (lifecycle), Scenario (warehouse + initial robots/tasks + seed/config), SimulationState (tick/status/events/metrics/paths/reservations), Experiment (configuration, real run records, aggregates, environment).

## Remaining limits

The 64 × 64 maximum-size stress test with 200 tasks did not finish in any of 12 frozen-weight variants. The user's 17-robot run was replayed exactly at tick 353 with 1/200 transports and zero collisions. At 16× all 50 API health probes succeeded and the terminal state reached the WebSocket client. Bidirectional contention led to a rejected swap and both robots ranked waiting above retreat. In six 32-robot variants, the fleet stayed idle through tick 30. On the reported layout all 6,400 robot–task assignments were initially feasible, but the model ranked idle above every task for every robot. The open 17-robot variant reached 191/200. The stress runs used isolated weights and stores. Evidence and reproduction are in docs/experiments/neural-max-stress/report.md.

CBS can time out on large conflicts; prioritized planning is incomplete. Charging uses a conservative shortest-path reserve and can safely fail on excessive detours. Active sessions are memory-only, with one backend worker and an eight-session cap. The platform is a local research application without authentication or continuous physical dynamics. 3D uses authored Blender GLBs; per-part animations and hardware-specific FPS profiling remain future work. The 32-robot browser check verifies rendering, not planner throughput or a frame-rate guarantee. Energy/admission heuristics do not imply global optimality. ML is supervised simulation-only learning, with explicit retraining after automatic data collection. Completed-task selection bias, fixed station admission and out-of-distribution maps/planners limit generalization. Route features see one nominal BFS path and 64 steps of existing plans, not future replanning; minimizing local ETA does not guarantee warehouse completion. Narrow passages expose additional NO_PLAN failures. Prediction accuracy does not imply a faster warehouse; current measurements do not establish general ML superiority. Generator geometry is procedural, not learned. ML data/model/job JSON currently grows without retention or pagination; intended for local research use.

## Reproduce the full-scenario check

```bash
uv run --directory apps/backend python - <<'PYTHON'
from app.core.demos import demo
from app.simulation.engine import Engine
for size in ('small', 'medium', 'large'):
    scene = demo(size)
    for planner in ('prioritized', 'adaptive', 'cbs'):
        config = scene.config.model_copy(update={'planner': planner, 'timeout_seconds': 2, 'max_nodes': 2000})
        engine = Engine(scene.model_copy(update={'config': config}), f'{size}-{planner}')
        for _ in range(1500):
            engine.step()
            if engine.state.status in ('COMPLETED', 'FAILED', 'STOPPED'):
                break
        print(size, planner, engine.state.status, engine.state.tick, engine.state.metrics.completed_tasks, engine.state.error)
PYTHON
```
